### 규칙 준수

- **기본값 = 기존 동작**: 저장값이 없으면 아무것도 적용하지 않음(E2E로 초기 상태 동일 확인). 오프셋 0, 커버 0, 어둡기 0.35(기존 CSS), 나머지는 꺼짐.
- **오프셋**: 판정 범위(175/300ms 등)는 그대로. `노트/판정 시간 = 오디오 시간 - 오프셋`으로 보정값을 더하는 방식이고, 곡 시작 때 고정됨. 영상 싱크는 실제 오디오 시간 기준.
- **저장**: `localStorage["djon.settings"] = {version: 1, ...}`. 없는 값은 기본값으로 채우고, 범위/타입을 보정하고, 깨진 JSON이면 기본값을 씀. 오토플레이와 랜덤 기믹 테스트는 실수로 켜둔 채 운영되지 않게 저장하지 않음.
- **기존 데이터 호환**: 기존 userProfile.gameSt/preference 구조는 그대로 쓰고 필드만 추가함.
- 자동 측정: 곡 선택 ESC → 설정 → "자동 측정" → 삑 소리 12번에 맞춰 아무 키 → 중앙값을 제안 → Apply.

### 제안만 함 (지시한 디자인이라 안 바꿈)

1. 판정 텍스트를 기어 중앙 상단 또는 판정선 아래로 내리는 것(DJMAX/EZ2ON은 노트 진행 경로를 가리지 않게 반투명·작게 표시). 지금은 판정선 바로 위 노트를 가림.
2. 결과 화면에 osu!식 타이밍 분포 막대그래프(현재는 숫자만 표시).
3. 빠른 재시작 키(osu!의 `~` 길게 누르기): 축제에선 실수로 눌릴 수 있어 넣지 않음.
4. 모바일: 기어 너비 500px 고정이라 390px 폭 폰에선 바깥 레인이 잘림. 너비 변경 금지라 그대로 둠(축제 PC 대상이면 문제없음).

## 6. 직접 확인할 체크리스트 (축제 PC, exe 재빌드 후)

1. `npm run electron:build` 후 exe 실행. 곡 6개 각각 로딩 → 플레이 → 결과까지 문제없는지.
2. **FPS 표시**(좌상단): kamui 연타 구간에서 50 이상 유지되는지. 떨어지면 ESC 설정에서 "노트 타격 이펙트"를 끄고 비교.
3. 로딩/Get Ready 중 ESC 연타: 음악이 먼저 나오거나 두 번 겹쳐 나오지 않는지.
4. 플레이 중 Alt+Tab(또는 윈도우 키) → 돌아와서 Resume: 첫 입력이 씹히지 않는지, 키 빔이 켜진 채 남지 않는지, 카운트다운 중 Alt+Tab 시 메뉴가 유지되는지.
5. 롱노트를 누른 채 ESC → Resume: 그 롱노트가 BREAK 처리되고 다음 노트는 정상인지(질문 C3 참고).
6. 일시정지 → Restart: 첫 노트가 겹쳐 나오지 않는지.
7. 일시정지 중 노트가 멈춘 채 보이는지.
8. ESC 설정 → 키 배치 변경, 키 빔 끄기 → Apply → 한 곡 끝까지 → 결과 → 다음 곡에서도 유지되는지 → **앱을 껐다 켜도 유지되는지**.
9. 오디오 오프셋 자동 측정 → Apply → 플레이 감각이 맞는지. 결과 화면 TIMING의 AVG가 0 근처인지.
10. 효과음 0% → 메뉴 효과음이 안 나는지.
11. No Fail 켜고 일부러 미스 → 게임오버 없이 끝까지 진행되는지.
12. 오토플레이 켜고 한 곡: 미스 없이 진행되는지, "AUTO PLAY" 표시가 뜨는지. 앱을 재시작하면 꺼져 있는지.
13. 20~30판 연속 운영 후에도 느려지지 않는지(작업 관리자 메모리).
14. 실제 모니터 해상도에서 판정선(CSS 선)과 노트가 맞는지(기존 확인 항목).

## 7. 검증에 쓴 것

- 단위 테스트: settings(기본값/부분 저장/범위/버전/깨진 JSON), 채보 정리(정렬/제거/실제 채보 동일), 레인 색.
- E2E(빌드 결과물 + 헤드리스 Chromium): A1~A7 각각 **수정 전 빌드에서 재현 → 수정 후 통과**, 설정 11항목, 오프셋 자동 측정(+50ms 입력 → +50ms), 회귀 10종, PC 1920×1080/모바일 390×844 캡처.
- 매 수정마다 `npm run build`(webpack) 통과. ESLint는 기존 prettier/App.vue 경고 외 새 오류 없음.
- 보호 수치 확인: 판정선 `canvas.height - 320`/CSS `bottom: 320px`, 기어 125px×4, HIT_WINDOW 175, EARLY_MISS 300, 미스 -9, 리드인 2초 그대로.

## 8. 추가 작업: 테마 2 (MILITARY HUD)

- 참고: MUSYNX: RETURN (공개 소개 기준 "SF 밀리터리 스타일 비주얼"). 이 작업 환경에선 YouTube/Steam 접속이 막혀 **영상을 직접 보지 못했음** → 공개 소개와 시리즈 특징으로 해석. 실제 화면과 다르면 스크린샷을 주면 맞춰 조정.
- 바꾼 것: 색(건메탈/앰버/본화이트), 직각 모양, 꺾쇠 브래킷, 격자·주사선 배경, 경고 줄무늬, 모노스페이스 숫자, 캔버스 노트/기어/키 빔 색.
- 안 바꾼 것: 판정 체계, 판정 표시(글자/콤보/FAST·SLOW/타격 이펙트 판정색/결과 판정 행·랭크 색), 판정선 위치, 기어 크기.
- 모바일 미지원 결정 → 사용 중 화면의 모바일 전용 CSS 삭제. 위 4장 '모바일' 관련 항목은 무시.

### 테마 관련 추가 기능 제안 (구현 안 함)
1. 테마별 타격 이펙트 모양(예: 테마 2는 원형 링 대신 사각 브래킷이 퍼지는 이펙트). 판정색은 그대로 두고 모양만 변경.
2. 테마별 UI 효과음 세트(테마 2: 무전기/기계음 클릭).
3. 테마 2 전용 곡 선택 연출: 곡을 바꿀 때 "TARGET LOCKED" 스캔 라인 애니메이션.
4. 테마 2 결과 화면의 "MISSION REPORT" 레이아웃(지금은 색/장식만 바뀜).
5. 판정 표시도 테마에 맞춘 버전을 옵션으로 추가(현재 고정이 원칙이라 켜는 옵션으로만).

### 테마 2 교체 (AFTERGLOW)
- 사용자 요청으로 테마 2를 MILITARY HUD → AFTERGLOW(해 질 녘 시티팝)로 교체. 색뿐 아니라 화면 배치도 테마 2 전용으로 재구성(곡 선택 좌우 반전, 점수 카드 이동, 일시정지 오른쪽 패널, 결과 2단 등).
- 판정 체계/판정 표시/판정선·기어 기하는 그대로(테마 1과 수치 비교로 확인).
